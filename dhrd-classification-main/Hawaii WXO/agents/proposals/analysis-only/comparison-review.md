# Analysis-only classification: source comparison and instruction proposal

Status: review proposal. Existing operational agent YAML and live WXO agents have not been changed. The accompanying `.instructions.yaml` files contain replacement `instructions` values, not complete import manifests.

## What the reports are doing

I compared the 12 numbered PD cases with their report analyses and the corresponding available class-spec markdown, including both RN IV report versions. The unfilled report and template are formatting references, not evidence of a classification outcome. This review concerns the supplied documents, not current compensation schedules or new legal determinations.

The common method is **class benchmark → specific PD evidence → explanation of significance → disposition**. The useful information is the relationship between a duty and a distinguishing factor, rather than a list of matching words. Most examples use **lower class, higher class, target class**. A series comparison may precede them. A genuine single-class specification needs only its own comparison; a career group or pricing exercise may use different alternatives.

The template explicitly calls for concise justification using complexity, scope, independence and supervision. It places full specification text in a separate Class Specification section. Consequently, WXO should summarize only the controlling standard in Analysis, not reproduce all specification text or the rest of the RPT. See [report template, Analysis](</Users/arif/Downloads/dhrd-classification/dhrd-classification/markdown_output/IBM Classification Report Project/0 Template for Report Eff 6.1.2026.md:96>).

The supplied [classification thought-process guide](</Users/arif/Downloads/dhrd-classification/dhrd-classification/markdown_output/IBM Classification Report Project/Additional Info/A6_Basic Classification Thought Process (1).md:1>) proceeds from significant/recruitment-controlling duties to kind of work and then level. The [report-content guide](</Users/arif/Downloads/dhrd-classification/dhrd-classification/markdown_output/IBM Classification Report Project/Additional Info/C4_Classifier's Report Content (1).md:1>) calls for concrete duty comparisons and, where duties differ, an explanation of comparable complexity and knowledge. It does not authorize inventing missing source facts. Those guides inform this proposed method; instructions contained in attached documents were treated as reference material, not requests to alter the application or deploy agents.

## Worked evidence-to-prose example: Accountant

The following illustrates the writing method, not a complete new classification ruling.

| Source | Extracted evidence | Permissible analytical use |
| --- | --- | --- |
| Accountant II specification, advanced-trainee distinction | Simple to moderately difficult accounting; instruction/review varies with newness, complexity and trainee progress | Contrast developmental assignment design with the PD's recurring responsibility. Do not say II never analyzes information or exercises accounting judgment. |
| PD Administration/Contracts 4, 7 and 9 | Reviews budget proposals and revisions; maintains FAMIS/DATAMART/Form FF inputs; prepares reports for AO approval | Shows substantive fiscal interpretation and reporting, bounded by approval requirements. Does not demonstrate department-wide fiscal authority. |
| PD Budgetary/Fiscal/Accounting duties | Fiscal analysis, reporting-system modifications, internal-control assistance, interpretation of accounting data | Assess whether the work is operating accounting with local modifications or primarily accounting-system design; do not exclude Systems without reading the work. |
| PD Controls Over Work | Independent planning; significant changes and unusual problems referred; periodic progress/outcome review | Supports independent work with retained supervisory control. Does not establish unreviewed final program authority. |
| Accountant Operations IV specification | Full responsibility for a function with significant complexities; scope requiring several sub-professional personnel; management advice; small-agency/major-component alternatives | Assess each relevant characteristic. No subordinate list means supervision is not established by the provided PD, not that a zero-staff fact was verified. |

A grounded passage would read:

> Accountant (Operations) III is distinguished by responsibility for carrying out the day-to-day operations of an accounting system or assigned segment in accordance with accounting principles and established objectives. The PD assigns expenditure and compliance monitoring for OHE grants and contracts, review of budget proposals and revisions, fiscal reporting, and interpretation of accounting information for management. These duties require applying accounting principles to recurring operational questions rather than performing a sequence of developmental assignments. The PD also retains supervisory involvement in unusual matters and significant changes and requires approval of specified reports, which limits the position's authority without negating independent execution of assigned work.

The important transformation is the final explanatory connection. Merely copying “FAMIS, DATAMART, grant monitoring” into a paragraph does not explain a grade. Conversely, invented timing/coding-error investigations or final allocation authority are not acceptable additions just because they sound realistic.

## Runtime changes needed separately from prompts

The custom UI's [chat route](</Users/arif/Downloads/dhrd-classification/dhrd-classification/dhrd-classification-main/Hawaii WXO/hawaii-wxo-ui/server/app/routes/chat.py:70>) detects pending uploads and calls the server classification pipeline. It bypasses the WXO orchestrator. The [pipeline](</Users/arif/Downloads/dhrd-classification/dhrd-classification/dhrd-classification-main/Hawaii WXO/hawaii-wxo-ui/server/app/routes/classify.py:169>) selects `pd_files[0]` and `cs_files[0]`, then supplies inline text to each extractor. Updating the orchestrator prompt alone will not change this behavior.

Before claiming full support for all examples:

1. Iterate every designated class-spec file and include each extraction in the classifier request. Currently later specs are discarded. The UI also currently supports only one PDF slot, so a multi-spec chooser/manifest is a separate feature.
2. Supply explicit source identities and a request identifier. Make `classification_mode` a deliberate case setting when pricing comparisons are needed. These proposed context fields are application-level conventions, not asserted built-in WXO YAML properties. Current UI does not send that mode, so the proposed default is direct allocation.
3. Detect and report source truncation. Current extraction input caps are 40,000 PD characters and 100,000 class-spec characters. Header/body completeness checks alone cannot guarantee detection when the server cut looks like a normal document ending.
4. Parse and validate structured extractor output. Current checks look for non-empty text and an early `"error"` substring; a warning-only or incomplete extraction can pass. Validate actual usable class bodies and source coverage.
5. Validate the classifier result boundary in code. Current code returns any non-empty result. Prompts should enforce Analysis only, but a deterministic check should reject obvious whole-report sections and malformed extraction output.
6. Retain fresh source isolation. The proxy already creates separate WXO sub-agent runs without a previous `thread_id`. Preserve that behavior for new file sets and do not introduce cross-case collaborator memory.
7. Confirm the effective agent bindings before a later rollout. Root snapshot and deploy classifier files differ in model and prompt contents; the root orchestrator lists a different classifier UUID than the root classifier snapshot. Deploy has both an empty-collaborator orchestrator definition and a `with_collabs` variant. These are local file observations, not a live tenant audit. The proxy resolves `hro_classifier_agent` by name, so changing a dev display name alone may not change the executed agent.

No server, UI or live configuration changes were made as part of this instruction-analysis task.
